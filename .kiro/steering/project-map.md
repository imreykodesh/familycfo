# מפת הפרויקט (Project Architecture Reference)

לפני כל משימה קוראים את `PROJECT_MAP.md` בשורש הפרויקט. יש בו את הקבצים והתפקיד של כל אחד, המסכים ונתיבי ה-URL,
נתיבי ה-API, הטבלאות, מפתחות `settings`, מפתחות `localStorage`, הגשר לדסקטופ, משתני הסביבה והתלויות.
כללי החשבונאות (מה נחשב הוצאה, חיובי כרטיס, העברות, תשלומים, שדות שנערכו ידנית) נמצאים ב-`CLAUDE.md` / `AGENTS.md`.

## כלל עדכון

משימה שמוסיפה, משנה, משנה שם או מוחקת אחד מאלה מעדכנת את הסעיף המתאים ב-`PROJECT_MAP.md` **באותה משימה, לפני שהיא מסומנת כגמורה**:

- קובץ או תיקייה (ותפקידם)
- פונקציה ציבורית מרכזית (export שמשתמשים בו מחוץ לקובץ)
- מסך או פרמטר URL של מסך
- נתיב API, או שינוי ברשימות של הצ'אט ב-`src/agent/mcp.ts` (`API_PATHS`, `WRITE_PATHS`, `AGENT_SETTINGS`)
- טבלה או עמודה (= מיגרציה חדשה בסוף `src/db/migrations.ts`; לא לערוך מיגרציה ששוחררה) — ולעדכן את "המיגרציה הבאה"
- מפתח `settings`, מפתח `localStorage`, ערוץ IPC של הדסקטופ
- משתנה סביבה
- תלות חיצונית (npm או שירות מבחוץ)
- סקריפט (`package.json`, `.cmd`, `scripts/`)

## הצ'אט (agent/)

- מסך חדש, או פרמטר URL חדש → לעדכן את "Links into the app" ב-`agent/CLAUDE.md`.
- נתיב שינוי חדש שהצ'אט צריך → להוסיף ל-`WRITE_PATHS` ולטבלת "Changing data" ב-`agent/CLAUDE.md`.
  לא לפתוח לצ'אט: משיכה, OTP, פרטי כניסה, הצ'אט עצמו, העלאת קבצים, הגדרות ה-AI והשירותים החיצוניים.
- `sql` נשאר לקריאה בלבד.

## תיעוד

- שינוי ארכיטקטורה או כלל → `CLAUDE.md` **ו-**`AGENTS.md` (אותו תוכן, רק הכותרת שונה).
- שינוי שהמשתמש רואה (פקודה, הגדרה, פרטיות) → `README.md`.

## סדר צעדי הסיום (תמיד בסדר הזה)

1. `PROJECT_MAP.md` (אם רלוונטי)
2. `CLAUDE.md` / `AGENTS.md` / `README.md` / `agent/CLAUDE.md` (אם רלוונטי)
3. `npm run check` — עובר בלי שגיאות
4. commit, push ומיזוג ל-`main` לפי `.kiro/steering/git-sync.md`
